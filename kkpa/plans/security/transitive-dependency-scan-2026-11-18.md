## Context

`jbh-personal-finance` already runs Trivy in CI (`.github/workflows/ci.yml`, job `security-scan`).
The scan has two problems:

- It reads `pom.xml` files offline. It skips any POM missing from `~/.m2`, so it can miss
  transitive dependencies.
- It never fails (`exit-code: 0`).

The `main` report from 2026-11-15 shows 9 unique CVEs: 1 HIGH, 4 MEDIUM, 4 LOW.
The HIGH is CVE-2026-102554 in `com.google.guava:guava` 33.5.0-jre, fixed in 33.7.2.

Decisions made with the user:

- `cyclonedx-maven-plugin` writes the exact dependency list that Maven resolves (an SBOM).
  The plugin does not scan. Trivy scans the SBOM.
- OWASP Dependency-Check was rejected. It needs an NVD key and a data cache, and it can add
  false positives.
- The check fails on HIGH or CRITICAL only when a fix exists.
- This change moves `guava` to 33.7.2-jre, so the first run can pass.
- No tests. The change is config only and adds no Java logic.

Limits:

- A red check does not block a merge today. The `protect-main` ruleset has no required status
  checks. This plan does not change that.
- MEDIUM and LOW findings (`logback-core` 1.5.6, `opentelemetry-api` 1.57.0) are out of scope.
- If the scan finds another fixable HIGH or CRITICAL, stop and show it to the user.
  Do not add it to `.trivyignore` without approval.

This plan changes two repos, with one branch and one PR each. Never make one commit across repos.
`main` is protected in both.

### 2. Add the CycloneDX plugin and the guava version

**File `pom.xml` (repo root)**

- In `<properties>`, add:

```xml
<cyclonedx-maven-plugin.version>2.9.3</cyclonedx-maven-plugin.version>
<guava.version>33.7.2-jre</guava.version>
```

- In `<build><pluginManagement><plugins>`, after the `spotbugs-maven-plugin` entry, add:

```xml
<!-- CycloneDX: writes the resolved dependency list (SBOM) that Trivy scans in CI -->
<plugin>
  <artifactId>cyclonedx-maven-plugin</artifactId>
  <configuration>
    <outputFormat>json</outputFormat>
    <projectType>application</projectType>
  </configuration>
  <groupId>org.cyclonedx</groupId>
  <version>${cyclonedx-maven-plugin.version}</version>
</plugin>
```

- In `<dependencyManagement><dependencies>`, after the `quarkus-bom` entry, add:

```xml
<!-- Overrides the Quarkus BOM to fix CVE-2026-102554. Remove when the BOM ships 33.7.2 or newer. -->
<dependency>
  <artifactId>guava</artifactId>
  <groupId>com.google.guava</groupId>
  <version>${guava.version}</version>
</dependency>
```

**File `jbh-z-assembly/pom.xml`**

This module packages the app, so its dependency tree is what ships.
In `<build><plugins>`, after the `maven-failsafe-plugin` entry, add:

```xml
<!-- Writes target/bom.json during verify. image.yml runs only package, so it is not affected. -->
<plugin>
  <artifactId>cyclonedx-maven-plugin</artifactId>
  <executions>
    <execution>
      <goals>
        <goal>makeBom</goal>
      </goals>
      <id>cyclonedx-bom</id>
      <phase>verify</phase>
    </execution>
  </executions>
  <groupId>org.cyclonedx</groupId>
</plugin>
```

- Test scope stays out. This is the plugin default, and test libraries do not ship.
- Expected outcome: `verify` will write `jbh-z-assembly/target/bom.json`.

```yaml
- name: Download SBOM
  uses: actions/download-artifact@v8
  with:
    name: sbom
    path: sbom

- name: Scan files for secrets
  uses: aquasecurity/trivy-action@ed142fd0673e97e23eac54620cfb913e5ce36c25 # v0.36.0
  with:
    scan-type: 'fs'
    scan-ref: '.'
    scanners: 'secret'
    format: 'table'
    exit-code: '0'

- name: Generate Trivy report file
  uses: aquasecurity/trivy-action@ed142fd0673e97e23eac54620cfb913e5ce36c25 # v0.36.0
  with:
    scan-type: 'sbom'
    scan-ref: 'sbom/bom.json'
    format: 'json'
    output: 'trivy-results.json'
    exit-code: '0'

- name: Check for fixable HIGH and CRITICAL
  uses: aquasecurity/trivy-action@ed142fd0673e97e23eac54620cfb913e5ce36c25 # v0.36.0
  with:
    scan-type: 'sbom'
    scan-ref: 'sbom/bom.json'
    format: 'table'
    severity: 'HIGH,CRITICAL'
    ignore-unfixed: 'true'
    exit-code: '1'
```
